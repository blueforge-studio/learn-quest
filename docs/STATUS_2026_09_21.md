## P0.1 · LFS — not a server outage

- **Server is up.** Authenticated batch + download on lq-core returned 200
  with a matching sha256; the batch endpoint answers normally on all 8 lq-*
  repos checked (core, english, nordic, romance, east-asian, slavic,
  reading, cards).
- **The 2026-09-20 smoke gave a false negative.** `scripts/ci/lfs-smoke.sh`
  probed bare `/info/lfs`, which Gitea 404s even with LFS healthy. It now
  POSTs `<repo>.git/info/lfs/objects/batch` (404 = down; 401/200 = up).
  The CX33 compose-env recovery steps in the roadmap are not needed.
- **The "modified files" noise is in the repos, not the server.** Files were
  committed as raw blobs on paths `.gitattributes` marks `filter=lfs`; the
  clean filter makes the working file a pointer, which never matches.
  Confirmed in lq-core (127/127), lq-romance and lq-celtic (40/40 sampled).
- **Fix:** one `git add --renormalize .` commit per repo on main, then
  `git pull && git lfs pull` in existing checkouts, then rebase.
  Pilot: **lq-core#71** (141 files, all objects verified on the server).
  Before doing an app repo, confirm its deploy path runs `git lfs pull`
  (see `.claude/agents/lfs-deploy.md`) — unlike lq-core's dev-only
  `apps/web`, app repos ship these files.

Unblocks, once each repo is renormalized: P1.4 app-shell 0.15 rebases,
the remaining P2.4 per-app generators.
