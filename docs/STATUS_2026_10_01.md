## Also in scope: publish-changed devDeps defect (forge-git peer audit)

Fleet-wide audit (blueforge-org#219) found the `publish-changed.ts` devDeps defect in the
`@learnquest` scope: **2 distinct script bodies × 2 checkouts** (`lq-core` DR-derived body;
`lq-tools` hash-equal to content-studio), plus a drifted legacy body in the
learn-quest-monorepo `lq-core` copy. Defect: changed-detection loops over `deps + peers` only,
so a future PR adding a devDep cross-import would strand the dependent package unpublished.
Recommended fix: a separate pre-build set (`dep + peer + dev`) for the loop/guard — **do not
widen `internalDeps`** (it also drives publish ordering). **Fix PRs opened this session:
lq-core#137 and lq-tools#75** (both add `internalDepsWithDev` used only by the publish loop's
failure guard; `expandWithDependents` keeps dep+peer; both dry-run verified). The drifted
legacy body in the learn-quest-monorepo `lq-core` checkout is a stale github-mirror on a
feature branch — refresh from forge-git main rather than patching a third body. After merge:
republish lq-core + lq-tools (local 09-21 token is the only one with @learnquest publish
scope). See memory `project_publish_changed_devdeps_fix_2026_10_01.md`.
