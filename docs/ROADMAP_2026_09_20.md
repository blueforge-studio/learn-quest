## P0 · Foundation blockers — nothing ships until these move

#### P0.1 · Restore CX33 LFS subsystem (forge-git#118)

**Source:** today's discovery + `forge-git-host-db-tuning.md` (same bug from 2026-09-07 → 2026-09-14, fixed then regressed).

**Why this matters:** Every lq-* repo with audio is broken. `git checkout`, `git rebase`, fresh clones all hit 404 on `/info/lfs`. P1.4 (app-shell 0.15 rollout), the remaining 6 P2.4 per-app generators, and any operator work that touches audio assets is blocked until LFS is restored.

**What blocks it:** CX33 SSH access. Operator-only.

**First step:**

```bash
ssh root@88.99.170.135
diff /opt/forge-git/docker-compose.yml /opt/forge-git/docker-compose.yml.bak-lfs-20260914T190659Z
# Expect: three env vars missing
# Re-add: GITEA__server__LFS_START_SERVER=true
#         GITEA__lfs__STORAGE_TYPE=local
#         GITEA__lfs__PATH=/data/git/lfs
docker compose up -d --no-deps gitea
curl -fsSL https://forge-git.blueforge.studio/blueforge-studio/forge-git.git/info/lfs   # expect non-404
```

**Owner:** Operator. Smoke script `learn-quest/scripts/ci/lfs-smoke.sh` is ready for the operator (or forge-git peer) to wire into CI as an advisory per-PR + weekly sweep.

**If storage was preserved:** `git lfs pull` from a local clone rehydrates, no operator action beyond the docker-compose fix.

**If storage was lost:** Recovery path is `git lfs push --object-id <forge-git url>` from a clone with objects — same procedure that recovered `lq-english` 447 objects in September. R2 is the source of truth for audio per `feedback_use_project_sync_scripts.md` — repopulate via `lq-operations/scripts/sync-to-storage.ts` if needed.
